## Топ-материалы

### 1. OpenAI: Dreaming — better memory for ChatGPT
- **Источник:** OpenAI, 2026-06-04: https://openai.com/index/chatgpt-memory-dreaming/
- **Evidence:** OpenAI описывает memory synthesis для ChatGPT с фокусом на more up-to-date, useful и scalable memory; в публичных пересказах отдельно подчеркивают борьбу с устаревшей и неточной памятью.
- **Inference для SiaMentor:** Habit companion должен синтезировать память после check-in, но next action не должен опираться на неподтвержденные или устаревшие выводы.
- **Практический вывод:** Ввести memory transparency line: "Помню из вчерашнего check-in: X" + affordance "неверно/забыть" до генерации следующего действия.

### 2. User backlash signal around persistent memory
- **Источник:** Reddit/OpenAI discussion, 2026-06-05: https://www.reddit.com/r/OpenAI/comments/1twwimu/openai_gives_chatgpt_a_new_dreaming_memory_system/
- **Evidence:** Обсуждения вокруг upgraded memory быстро уходят в вопросы контроля, приватности и опасения, что помощник слишком много помнит.
- **Inference для SiaMentor:** Для D2C book-to-habit продукта "память" продает continuity, но без контроля превращается в trust risk.
- **Практический вывод:** В MVP memory должна быть маленькой, доменной и редактируемой: хранить только goal, trigger, completed action, friction, confidence и source check-in, а не общий life profile.

### 3. Cyberheart: AI companions with memory in 2026
- **Источник:** Cyberheart, crawled 2026-06-05: https://cyberheart.ai/features/best-ai-companions-with-memory-in-2026/
- **Evidence:** Consumer companion market явно сравнивает продукты по continuity, cross-session memory и контролю над memory.
- **Inference для SiaMentor:** Пользователь будет судить AI companion не по "умности", а по ощущению, что он помнит полезные детали между днями.
- **Практический вывод:** В Day 2–7 UI показывать remembered context как часть daily action, иначе memory останется backend feature и не повысит perceived value.

### 4. OpenAI memory coverage in press
- **Источник:** Cinco Dias/El Pais, 2026-06-05: https://cincodias.elpais.com/smartlife/lifestyle/2026-06-05/chatgpt-recordara-mucho-mejor-quien-eres-y-que-necesitas-gracias-a-su-nueva-memoria.html
- **Evidence:** Пресса объясняет новую memory architecture как способ работать с накопленным контекстом, делать память свежее и уменьшать риск неважной/старой информации.
- **Inference для SiaMentor:** Даже mainstream coverage учит пользователя ожидать "актуальную память"; устаревшее remembered context в habit companion будет восприниматься как ошибка продукта.
- **Практический вывод:** Добавить stale-memory UX: если последний check-in старше N дней, показывать "давно не обновляли контекст" и предлагать restart/grace-day flow.

### 5. Learning companion design still matters outside EdTech wedge
- **Источник:** arXiv 2605.04816, 2026-05-06: https://arxiv.org/abs/2605.04816
- **Evidence:** Paper про AI learning companions делает акцент на adaptation, transparency, accountability и learner agency, а не только task performance.
- **Inference для SiaMentor:** Book-to-habit не должен превращаться в пассивный советчик: пользователь выбирает trigger, подтверждает действие и корректирует memory.
- **Практический вывод:** Удерживать agency в Day 1–3: AI предлагает micro-action, пользователь выбирает trigger и confidence; check-in собирает факт, а не свободный дневник.

## Evidence vs inference for SiaMentor
- **Evidence:** Phase 8 roadmap уже задает правильный loop: book -> 7-day plan -> check-in -> streak/grace day -> paywall after 3 completed tasks.
- **Evidence:** Свежая OpenAI memory волна делает актуальность и корректность памяти category expectation для AI companions.
- **Evidence:** Consumer discussion вокруг memory показывает trust/privacy risk, если память непрозрачна или слишком широкая.
- **Inference:** SiaMentor должен продавать "observable continuity": каждый день видно, какой факт из прошлого check-in повлиял на следующий action.
- **Inference:** Лучший MVP data moat — не большой чат-лог, а маленький habit graph с evidence snippets и user correction.

## Решение дня
Не расширять продуктовую стратегию и список книг. Следующий execution layer: сделать memory видимой, исправляемой и связанной с trigger consistency, а paywall строить на доказательстве трех completed actions.
