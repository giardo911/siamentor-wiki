## Топ-материалы

### 1. AgentSchool: education agents надо моделировать как state transition, а не persona role-play
- **Источник:** arXiv, 2026-05-28: AgentSchool: An LLM-Powered Multi-Agent Simulation for Education — https://arxiv.org/abs/2605.30144
- **Evidence:** Авторы предлагают multi-agent simulator, где student agents имеют weighted subject knowledge graphs, workflows и explicit misconceptions; teacher agents планируют/scaffold/reflect через Zone of Proximal Development.
- **Главная идея:** Учебный AI оценивается через изменение состояния learner-а, а не через убедительность ответа.
- **Почему важно:** Старый EdTech wedge SiaMentor мог бы выиграть от таких симуляций, но текущий book-to-habit wedge тоже нуждается в state transition: "пользователь хотел внедрить X" -> "выбрал триггер Y" -> "сделал/не сделал" -> "почему сорвался" -> "следующий шаг".
- **Практический паттерн:** Для Phase 8 хранить не длинный чат, а компактные состояния: `goal`, `book`, `trigger`, `current_day`, `last_action_result`, `friction_tag`, `next_micro_action`.
- **Риск/ограничение:** Симуляторы не заменяют реальных D2C пользователей. Не строить исследовательскую платформу; взять только принцип state-based eval.
- **Связь с unicorn-траекторией:** State transition + habit memory дают data moat: SiaMentor начинает знать, какие книжные идеи реально превращаются в поведение у разных сегментов.

### 2. Meta-Cognitive Memory Policy Optimization: качество памяти надо мерить по uncertainty, а не только по финальному успеху
- **Источник:** arXiv, 2026-05-28: Meta-Cognitive Memory Policy Optimization for Long-Horizon LLM Agents — https://arxiv.org/abs/2605.30159
- **Evidence:** Работа критикует recursive summaries за потерю task-relevant информации и semantic noise; предлагает Belief Entropy как proxy качества промежуточных summary.
- **Главная идея:** В long-horizon agent память ломается не сразу, а через маленькие плохие summaries, которые смещают belief state.
- **Почему важно:** Для SiaMentor 7-дневный план — короткий, но multi-session. Если агент неверно сожмёт "почему пользователь не сделал Day 2", персонализация Day 3 станет хуже.
- **Практический паттерн:** Ввести memory write eval: после check-in LLM должен записать 1-3 структурированных memory facts и отдельно confidence/uncertainty. Низкая уверенность -> не использовать как сильную персонализацию.
- **Риск/ограничение:** Paper про оптимизацию memory policies, а не готовый SaaS-паттерн. Для MVP нужен простой эвристический analog, не RL.
- **Связь с unicorn-траекторией:** Memory quality становится продуктовым moat только если память не загрязняется. Иначе персонализация ухудшит retention.

### 3. Temporal Stability in Math Task Assessment: model updates не гарантируют улучшение, few-shot/rubric примеры могут быть сильнее
- **Источник:** arXiv, 2026-05-28: Temporal Stability and Few-Shot Prompting in Math Task Assessment — https://arxiv.org/abs/2605.30151
- **Evidence:** В исследовании Gemini сохранял 58% accuracy после обновления, education-specific Coteach падал с 75% до 50%, а few-shot prompting восстанавливал/улучшал качество.
- **Главная идея:** Нельзя полагаться на "новая модель стала лучше"; для domain task нужны зафиксированные examples и regression eval.
- **Почему важно:** SiaMentor будет генерировать if-then actions из книг. Даже если модель обновится, качество micro-actions может дрейфовать.
- **Практический паттерн:** Создать маленький golden set: 3 книги x 3 дня x 2 цели пользователя. Проверять, что action <=10 минут, имеет clear trigger, связан с книгой, не звучит как generic self-help.
- **Риск/ограничение:** Работа про math task classification, не habit coaching. Переносим принцип temporal drift, а не предметную метрику.
- **Связь с unicorn-траекторией:** Надёжный generation quality повышает activation и снижает churn от "AI дал банальность".

### 4. GroupMemBench: multi-user memory пока слабая, BM25 иногда бьёт agent memory systems
- **Источник:** Microsoft Research, May 2026: GroupMemBench — https://www.microsoft.com/en-us/research/publication/groupmembench-benchmarking-llm-agent-memory-in-multi-party-conversations/?lang=en
- **Evidence:** Microsoft пишет, что лучший memory system достигает только 46.0% average accuracy; knowledge update 27.1%, term ambiguity 37.7%; BM25 baseline сопоставим или лучше многих memory systems.
- **Главная идея:** "Добавим memory" не равно "получим персонализацию"; структура ingest/retrieval критична.
- **Почему важно:** Для SiaMentor рано строить social/multi-user или "tutor + peers" как core. Даже персональная memory должна быть speaker-grounded, а не просто векторная куча заметок.
- **Практический паттерн:** В Phase 8 хранить memory per user and per plan, с явными типами: preference, trigger, completed_action, friction, book_concept. Не смешивать всё в один history blob.
- **Риск/ограничение:** Benchmark про group conversations; SiaMentor MVP single-user. Но warning про memory ingestion применим.
- **Связь с unicorn-траекторией:** Сильная, типизированная персональная память может стать defensibility; неструктурированная память станет техдолгом.

### 5. OpenAI Workspace Agents: agent setup становится guided, controlled, observable
- **Источник:** OpenAI Help Center, 2026-05-28/29 release notes — https://help.openai.com/en/articles/10128477-chatgpt-enterprise-edu-release-notes
- **Evidence:** Workspace agents получили model/reasoning controls, role-based publishing, guided agent setup, speech output, smarter Slack thread replies; админы видят activity/usage analytics.
- **Главная идея:** Рынок двигается к агентам с setup questions, permissions, channels и analytics, а не к "одному чату".
- **Почему важно:** Для SiaMentor onboarding должен быть guided setup: не "что ты хочешь?", а 3-4 вопроса, которые создают action-ready plan.
- **Практический паттерн:** Онбординг Phase 8: book -> desired outcome -> default trigger -> preferred reminder window. Всё это сразу становится plan memory и влияет на Day 1.
- **Риск/ограничение:** OpenAI notes — enterprise/edu release, не consumer habit app. Не копировать enterprise controls в MVP.
- **Связь с unicorn-траекторией:** Чем лучше guided setup, тем выше activation; чем больше observable loop, тем быстрее улучшаются plan prompts/evals.

### 6. RevenueCat subscription retention: отменивших вернуть почти невозможно
- **Источник:** 9to5Mac summary of RevenueCat State of Subscription Apps 2026 Part 2, 2026-05-27 — https://9to5mac.com/2026/05/27/new-report-shows-annual-app-subscribers-rarely-return-after-they-cancel/
- **Evidence:** По статье, more than half of trial cancellations happen on Day 1; Month 1 accounts for 35% of annual cancellations; annual reactivation is just 5%; yearly renewals strong only после первого renewal.
- **Главная идея:** Платёжная стратегия не спасает слабый early value. Если пользователь отменил, winback почти не работает.
- **Почему важно:** Paywall после 3 completed actions лучше, чем ранний paywall до value moment. Но перед paywall нужно дать заметный progress artifact.
- **Практический паттерн:** Перед paywall показывать "ты внедрил 3 действия из Atomic Habits: X/Y/Z; следующий 30-дневный план закрепит это".
- **Риск/ограничение:** Материал на 4 дня старше идеального окна 1-3 дня, но прямо релевантен monetization/retention для consumer subscriptions.
- **Связь с unicorn-траекторией:** Сильный paywall timing повышает conversion без убийства retention; слабый timing создаёт churn, который трудно вернуть.
