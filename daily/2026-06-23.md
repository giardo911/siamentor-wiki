## Топ-материалы

### 1. The 74 / Stanford: access to AI tutors does not mean students will use them
- **Источник:** The 74, "Study: Giving Kids Access to AI Tutors Doesn't Mean They'll Use Them", 17 июня 2026: https://www.the74million.org/article/study-giving-kids-access-to-ai-tutors-doesnt-mean-theyll-use-them/
- **Evidence:** материал пересказывает Stanford research: students left alone with a tutoring bot spent just 2-5 minutes interacting.
- **Inference для SiaMentor:** open-ended AI access не создает habit loop. SiaMentor должен сужать первый опыт до одного действия из книги и быстрого receipt, иначе пользователь "посмотрел план" и ушел.
- **Практический вывод:** считать activation только через `book_habit_day1_completed`; в onboarding добавить `do_later_recovery_hook`, если действие не выполнено сразу.

### 2. Chalkbeat: research on AI tutoring broke against usage friction
- **Источник:** Chalkbeat, "Research on AI tutoring ran into a problem: Most students wouldn't use it", 17 июня 2026: https://www.chalkbeat.org/2026/06/17/ai-tutoring-research-ran-into-problem-students-wouldnt-use-it/
- **Evidence:** свежий education signal прямо формулирует проблему: полезность tutor нельзя доказать, если большинство не возвращается к нему регулярно.
- **Inference для SiaMentor:** daily check-in — это не secondary feature, а core product mechanism. Главный экран должен вести к практике, а не к генерации новых объяснений.
- **Практический вывод:** Day 2 surface: receipt прошлого действия -> memory receipt -> if-then trigger -> микро-действие до 10 минут -> check-in.

### 3. K-12 Dive: access alone does not improve engagement or outcomes
- **Источник:** K-12 Dive, "AI tutor access alone doesn't equate to student gains, study says", 18 июня 2026: https://www.k12dive.com/news/ai-tutor-access-alone-doesnt-equate-to-student-gains-study-says/823214/
- **Evidence:** Stanford study framed as warning for AI tutoring pilots: mere access is not enough to create meaningful engagement and improve outcomes.
- **Inference для SiaMentor:** для adult D2C users friction еще выше, потому что книга конкурирует с рабочим днем. Нужно проектировать default action как 5-10 минут, привязанное к жизненному trigger.
- **Практический вывод:** добавить eval `action_too_large_or_unbound`: fail, если действие без trigger или больше 10 минут.

### 4. Vellum: persistent memory is now a personal AI differentiator
- **Источник:** Vellum, "10 Best Personal AI Assistants with Memory in 2026", опубликовано около начала июня 2026: https://www.vellum.ai/blog/best-personal-ai-assistants-with-memory
- **Evidence:** обзор сравнивает assistants по persistent memory, architecture и privacy model, а не только по model quality.
- **Inference для SiaMentor:** memory нужна, но в узком домене: goal, trigger, completed action, friction, confidence, source check-in. Широкий personality profile ухудшит trust.
- **Практический вывод:** Day 2-7 должен показывать memory receipt с действиями `верно / исправить / забыть` до генерации следующего шага.

### 5. RevenueCat: AI monetization premium coexists with retention gap
- **Источник:** RevenueCat, State of Subscription Apps 2026: https://www.revenuecat.com/state-of-subscription-apps/
- **Evidence:** RevenueCat показывает lower retained subscribers after 12 months для AI apps: weekly 1.2% vs 1.7%, monthly 6.1% vs 9.5%, annual 21.1% vs 30.7%.
- **Inference для SiaMentor:** paywall после 3 completed actions имеет смысл только как proof of progress. Если продавать просто "AI subscription", early WTP может превратиться в churn.
- **Практический вывод:** typed contract `HabitProofPaywall`: `completed_actions[3]`, `best_trigger_pattern`, `friction_adjustment`, `next_30_day_promise`, `free_continue_available`.

## Evidence vs inference for SiaMentor
- **Evidence:** локальный ROADMAP уже задает Phase 8 как book-to-habit loop: plan -> daily check-in -> streak/grace -> paywall after 3 completed tasks.
- **Evidence:** свежие AI tutoring материалы за 17-18 июня 2026 сходятся на одном: доступ к tutor без guided usage не дает engagement/outcomes.
- **Evidence:** market memory sources показывают persistent memory как expectation, а EDPS/governance контекст из предыдущих daily подтверждает privacy/control pressure для companions.
- **Inference:** MVP должен быть action-state machine, а не chat-first assistant: `plan_created -> day1_completed -> d1_return -> day3_completed -> proof_paywall_rendered`.
- **Inference:** memory и paywall надо реализовывать как user-visible contracts: проверяемая habit memory и evidence-backed paywall receipt.
