## Топ-материалы

### 1. RevenueCat Utilities 2026: AI apps слабее удерживают платящих пользователей
- **Источник:** RevenueCat State of Subscription Apps 2026 — Utilities, crawled last week: https://www.revenuecat.com/state-of-subscription-apps-2026-utilities/
- **Evidence:** RevenueCat показывает, что AI apps в utilities имеют ниже 12-month retention: 2.5% weekly, 6.1% monthly, 21.1% annually против 3.4%, 9.5%, 30.7% у non-AI.
- **Inference для SiaMentor:** "AI companion" нельзя продавать как фичу саму по себе. Paywall должен быть после конкретного доказательства изменения: пользователь выполнил 3 действия из книги.
- **Практический вывод:** В paywall copy использовать completed actions как proof: "ты сделал X/Y/Z; следующий шаг — 30-дневный план закрепления".

### 2. RevenueCat 2026 trends: problem of retention surfaced after AI apps became mainstream
- **Источник:** RevenueCat blog, State of Subscription Apps in 10 minutes, 2026: https://www.revenuecat.com/blog/growth/subscription-app-trends-benchmarks-2026/
- **Evidence:** RevenueCat связывает падение retention у AI apps с тем, что пользователи уже успели оценить реальную долгосрочную пользу после первой волны любопытства.
- **Inference для SiaMentor:** Первый wow от "книга в план" должен быстро превращаться в measurable habit loop: Day1 completed, D1 return, Day3 completed, D7 retained.
- **Практический вывод:** Не оптимизировать только генерацию плана. Оптимизировать completion chain и возврат на следующий день.

### 3. MemMachine: long-term memory выигрывает от сохранения ground truth и retrieval tuning
- **Источник:** arXiv, 2026-04-06: MemMachine: A Ground-Truth-Preserving Memory System for Personalized AI Agents — https://arxiv.org/abs/2604.04853
- **Evidence:** Работа утверждает, что persistent memory нужна для personalization/factual continuity, но RAG/context-window pipelines деградируют в multi-session interactions; система сохраняет эпизоды и оптимизирует retrieval, а не только ingestion.
- **Inference для SiaMentor:** Для habit companion опасно превращать check-in в сжатую "биографию пользователя". Лучше сохранять raw check-in evidence + typed derived fields.
- **Практический вывод:** В Phase 8 memory schema добавить ссылку на исходный check-in / короткий evidence snippet рядом с `friction_tag`, `trigger_viability`, `confidence`.

### 4. Useful Memories Become Faulty: continuously updated LLM memory может портиться
- **Источник:** Hugging Face Papers / arXiv 2605.12978, crawled 2 days ago: https://huggingface.co/papers/2605.12978
- **Evidence:** Paper page формулирует риск consolidated memory: LLM постоянно переписывает прошлые trajectories в textual memory bank, обещая self-improvement без parameter updates.
- **Inference для SiaMentor:** Если каждый check-in переписывает "профиль привычек", память начнет закреплять ложные обобщения. Нужен append-only event log + осторожные derived facts.
- **Практический вывод:** Memory write rubric должна отвечать: "это факт, наблюдение или предположение?" Предположения не должны попадать в durable memory без повторного подтверждения.

### 5. Cross-platform personalization: персонализация сдвигается от платформы к user-governed agent
- **Источник:** arXiv News, May 12 2026, crawled 3 days ago: https://www.arxivnews.org/en/articles/f9988df7-eafc-4a1e-b15c-6b1adeff4605
- **Evidence:** Материал описывает LLM agents, которые объединяют разрозненные пользовательские данные и дают рекомендации вне границ одной платформы.
- **Inference для SiaMentor:** В будущем moat может быть не в book catalog, а в пользовательском habit graph: цели, триггеры, фрикции, выполненные действия, контекст дня.
- **Практический вывод:** Даже в MVP важно проектировать exportable/portable habit state, чтобы не запереть ценность в чате.
