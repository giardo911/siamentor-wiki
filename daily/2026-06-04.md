## Топ-материалы

### 1. RevenueCat Social & Lifestyle 2026: AI apps удерживают хуже across durations

- **Evidence:** RevenueCat отмечает, что AI apps имеют более слабый retention по subscription durations; consumer surplus от AI не отменяет проблему долгосрочной полезности.
- **Inference для SiaMentor:** Paywall нельзя строить вокруг "у нас AI". Он должен появляться после visible proof: пользователь сделал 3 конкретных действия из книги и видит, что будет дальше.
- **Практический вывод:** В Phase 8 paywall sheet должен брать copy из completed actions, а не из generic value proposition.

### 2. Computing / RevenueCat: annual retention у AI apps 21.1% против 30.7% у non-AI
- **Источник:** Computing, "AI-powered apps struggle to keep subscribers, report finds", crawled last week: https://www.computing.co.uk/news/2026/ai-powered-apps-struggle-retain-subscribers
- **Evidence:** По пересказу RevenueCat, annual retention у AI-powered apps составляет 21.1%, у non-AI apps 30.7%; monthly retention тоже ниже.
- **Inference для SiaMentor:** Платный продукт должен быстро показать, что пользователь не просто получил план, а реально изменил поведение.
- **Практический вывод:** Главная аналитика на ближайший спринт: `plan_created -> day1_completed -> d1_return -> day3_completed -> paywall_proof_rendered -> paywall_clicked`.

### 3. Portable Agent Memory: memory portability becomes product architecture, not backend detail
- **Источник:** arXiv 2605.11032, published May 10 2026: https://arxiv.org/abs/2605.11032
- **Evidence:** Paper предлагает протокол переносимой, cryptographically verified memory transfer между разными AI agents.
- **Inference для SiaMentor:** Если habit graph станет ядром ценности, его нельзя проектировать как неструктурированный чат-лог. Пользовательская память должна быть явной и экспортируемой хотя бы концептуально.
- **Практический вывод:** В schema отделить append-only habit events от derived facts и предусмотреть stable identifiers для book, goal, trigger, action и check-in evidence.

### 4. MedMemoryBench: personalized memory needs evaluation, not only storage
- **Источник:** arXiv 2605.11814, published May 12 2026: https://arxiv.org/abs/2605.11814
- **Evidence:** Benchmarking memory in personalized healthcare подчеркивает, что memory-системы надо проверять на корректное использование персональных фактов в чувствительных сценариях.
- **Inference для SiaMentor:** Даже вне healthcare, ошибочная память о фрикции/триггере может ухудшить следующий action и доверие.
- **Практический вывод:** В golden set добавить memory-use checks: generated next action должен ссылаться только на confirmed facts или явно помеченные low-confidence inference.

### 5. Persistent AI Agents case study: durable routines создают ценность, но стоимость и cache/read profile важны
- **Источник:** arXiv 2605.26870, published last week: https://arxiv.org/abs/2605.26870
- **Evidence:** Case study описывает persistent agent setup с durable memory, local files, scheduled routines и большим объемом cached reads.
- **Inference для SiaMentor:** Daily habit companion может выигрывать от persistent routine, но unit economics ломаются, если каждый check-in тащит слишком много памяти.
- **Практический вывод:** Для MVP нужен memory budget: максимум N relevant facts/events в prompt, cheap routing для check-in, и eval на качество next micro-action при ограниченном context.
