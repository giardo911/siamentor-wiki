# 2026-06-17 — Action receipt после выполнения шага

## Фокус дня

Сделать post-action state сразу после выполненного действия: пользователь завершил микро-шаг из книги, видит короткий receipt прогресса, понимает что именно сохранено в habit memory, и получает мост к завтрашнему повторению. Это состояние должно закрывать петлю `книга -> действие -> привычка` до любого paywall.

## Проблема

Сейчас дизайн много говорит про Day 2-7 memory gate, recovery и proof paywall, но между "я сделал действие" и "приложение использует это завтра" нужен отдельный спокойный момент. Без него выполнение может ощущаться как одноразовая галочка, а память companion выглядит магической: пользователь не видит, какой факт из действия стал основой привычки.

## Дизайн-решение

После нажатия `Сделал` открывать mobile-first action receipt:

- Верх: `Действие засчитано` и маленький прогресс `1 из 3 до плана на 30 дней`.
- Book anchor: одна строка `Из книги: <идея/принцип>` без пересказа главы.
- Habit receipt: `Сегодня ты сделал: <completed_action>` и `Триггер: <trigger>`.
- Memory receipt: `Запомню для завтра: когда <trigger>, предложить шаг <=10 минут; препятствие: <friction или "пока не выбрано">`.
- Primary CTA: `Назначить завтрашний шаг`.
- Secondary action: `Исправить, что запомнить`.

Paywall остается заблокированным до 3 completed actions. В этом state можно показать только нейтральный progress hint: `После 3 действий покажем, какой ритм уже складывается`.

## Ключевые состояния

- `first_action_completed`: первый receipt, paywall progress `1/3`, фокус на завтрашнем шаге.
- `memory_needs_confirmation`: если friction/trigger неясны, secondary prompt просит выбрать один вариант вместо сохранения догадки.
- `third_action_completed_ready_for_proof`: receipt превращается в мост к proof paywall: `Уже есть 3 действия. Можно собрать 30-дневный план`.
- `memory_corrected`: пользователь меняет trigger/action/friction; receipt обновляется и помечает correction как нормальное действие, не ошибку.

## UX-copy

- Title: `Действие засчитано`
- Progress: `1 из 3 до персонального плана`
- Book anchor: `Идея из книги стала действием`
- Memory line: `Запомню только это: триггер, действие и препятствие для следующего шага.`
- CTA: `Назначить завтрашний шаг`
- Secondary: `Исправить память`
- Paywall hint before proof: `Сначала соберем 3 выполненных действия, потом покажем план на 30 дней.`

## Открытые вопросы

- Нужно ли просить confidence сразу в receipt или лучше оставить его для Day 2 check-in?
- Если пользователь сделал действие без выбранного trigger, блокировать receipt или мягко попросить выбрать trigger перед завтрашним шагом?
- Показывать ли streak в receipt с первого дня, или это преждевременно усиливает game pressure?
- Должен ли `Исправить память` открывать inline editor или отдельный compact bottom sheet?
