# 2026-06-19 - Proof paywall evidence contract

## Фокус
Сделать paywall после третьего выполненного действия доказательством прогресса: книга -> 3 действия -> найденный trigger pattern -> адаптация под friction -> предложение 30-дневного плана.

## Проблема
Если paywall появляется как обычная подписка на AI, пользователь видит обещание, а не результат. Для book-to-habit companion монетизация должна возникать только после того, как продукт уже показал: идеи из книги превращаются в повторяемые действия.

## Дизайн-решение
После `completed_actions.length >= 3` основной habit surface переходит в состояние `ready_for_proof`. Paywall не продает "умного помощника"; он показывает короткий proof receipt и предлагает продолжить уже начатую цепочку.

Evidence contract для paywall:
- `completed_actions[3]`: три конкретных выполненных действия с book anchor;
- `best_trigger_pattern`: осторожная формулировка повторяемого слота без ложной уверенности;
- `friction_adjustment`: что продукт уже уменьшил или изменил из-за барьера;
- `next_30_day_promise`: что станет регулярным планом после оплаты.

Экран остается mobile-first: сверху progress receipt, затем один вывод про trigger, затем предложение 30-дневного плана. Secondary action оставляет пользователя в бесплатном daily loop без сброса прогресса.

## Ключевые состояния
- `paywall_blocked`: меньше 3 completed actions, показываем только progress `n/3`.
- `ready_for_proof`: есть 3 completed actions, можно собрать proof receipt.
- `weak_pattern`: действия есть, но trigger неустойчивый; copy говорит "пока лучше сработало", а не "ты всегда".
- `friction_adjusted`: выбранный барьер уже изменил следующий шаг, это показывается как ценность.
- `trial_started`: пользователь начинает trial из proof paywall.
- `continue_free`: пользователь закрывает paywall и получает следующий маленький шаг без наказания.

## UX-copy
- Заголовок: "У тебя уже есть 3 действия из книги"
- Receipt: "Сделано: {action_1}, {action_2}, {action_3}"
- Pattern: "Пока лучше всего срабатывает: {best_trigger_pattern}"
- Adjustment: "Когда мешает {friction}, уменьшаем шаг до {adjusted_action}"
- Offer: "Собрать из этого 30-дневный план"
- CTA: "Продолжить с планом"
- Secondary CTA: "Пока продолжить бесплатно"
- Boundary line: "Помним только цель, триггер, действие и препятствие для следующего шага"

## Открытые вопросы
- Нужен ли minimum confidence для `best_trigger_pattern`, или достаточно cautious copy?
- Какие три действия показывать, если пользователь сделал больше трех до первого paywall view?
- Должен ли `continue_free` снова показывать paywall после следующего completed action или ждать нового паттерна?
- Что делать, если friction менялся каждый день и нет стабильной adjustment story?
