# 2026-07-14 — pending-sync receipt после offline action

## Фокус дня

Сделать состояние `offline_action_synced_review`: пользователь вчера выполнил offline action из verified memory, приложение синхронизировало receipt, а сегодня показывает проверяемый мост `книга -> offline действие -> привычка` перед следующим шагом и будущим proof paywall.

## Проблема

Offline fallback уже сохраняет habit loop без LLM и без generic error, но следующий день может выглядеть как обычный Day 2 экран. Если пользователь не видит, что pending receipt успешно принят и влияет на следующий шаг, доверие к памяти падает, а proof paywall после 3 действий выглядит слабее: одно из действий было "где-то офлайн", без явного доказательства.

## Дизайн-решение

На первом online return после offline completion показываем компактный review экран:

- Верхний статус: `Синхронизировано` + время синка, без технического жаргона.
- Receipt: книга, тезис, offline action, trigger, friction, `llm_calls_used=0`.
- Контроль памяти: `Верно`, `Исправить`, `Забыть`.
- Следующий микро-шаг: template-first действие <=10 минут, явно построенное из синхронизированного receipt.
- Progress: offline completion учитывается как обычное действие, например `2/3 до proof`.

Ключевой принцип: синк не должен быть отдельной технической победой. Он должен доказывать, что действие из книги стало частью привычки и продолжает следующий день.

## Ключевые состояния

- `offline_action_pending_sync`: действие выполнено offline, receipt локальный, progress виден как pending.
- `offline_action_synced_review`: сеть вернулась, receipt принят, пользователь проверяет память перед next action.
- `offline_receipt_correction`: пользователь исправляет trigger/friction/action до генерации следующего шага.
- `offline_receipt_forgotten`: пользователь удаляет receipt; progress не идет в proof eligibility, показывается recovery action <=5 минут.
- `synced_receipt_next_action`: следующий шаг собран template-first из verified/corrected receipt.

## UX-copy

- Статус: `Готово: вчерашнее действие сохранено`
- Receipt intro: `Я учту только это для следующего шага`
- Memory boundary: `Помню книгу, действие, trigger и помеху. Личные выводы вне этой привычки не сохраняю.`
- Next action label: `Сегодня продолжим с 7 минут`
- Correction CTA: `Исправить перед следующим шагом`
- Forget CTA: `Забыть это действие`

## Открытые вопросы

- Если sync failed, показывать retry inline на receipt или возвращать пользователя в offline pending state до следующего открытия?
- Считать corrected offline receipt eligible для proof paywall сразу или только после подтверждения следующего online action?
- Нужен ли отдельный event `offline_receipt_synced_verified`, или достаточно пары `offline_completion_synced` + `habit_memory_verified`?
