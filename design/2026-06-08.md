# Design iteration — 2026-06-08

## Фокус дня
Memory correction controls в daily check-in: строка "что SiaMentor помнит" + быстрые действия `верно / исправить / забыть`.

## Почему это важно
SiaMentor продает не просто summary книги, а переход "книга -> конкретные действия -> привычка". Для этого companion должен помнить, что реально сработало в жизни пользователя. Но память без контроля быстро выглядит как ложная персонализация: если приложение неверно запомнило trigger или friction, следующий action становится хуже и доверие падает.

## Дизайн-решение
В Day 2-7 check-in добавить компактный trust block перед сегодняшним действием:

- источник памяти: "из вчерашнего check-in";
- конкретный факт: trigger, completed action или friction;
- confidence простым языком: "похоже, это сработало";
- три действия: `верно`, `исправить`, `забыть`;
- после correction следующий action перестраивается до подтверждения выполнения.

## Ключевые экраны и состояния

1. **Today check-in / confirmed memory**
   - Верх: "Atomic Habits -> 7 дней -> привычка".
   - Progress: Day 2/7, streak 1, grace day доступен.
   - Memory line: "Помню из вчера: после кофе ты сделал 5 минут чтения."
   - Action: подтвердить, исправить или забыть факт.

2. **Correction drawer**
   - Поле с исходным фактом.
   - Быстрые chips: "другое время", "не сделал", "другая помеха", "не хочу сохранять".
   - CTA: "Обновить сегодняшний шаг".

3. **Forgotten memory state**
   - Memory line заменяется на честный fallback: "Ок, не использую вчерашний факт. Сегодня берем только книгу и цель."
   - Today's action остается конкретным, но без персональной ссылки на прошлый день.

4. **Confirmed state**
   - После `верно`: короткий success state "Запомнил для следующих дней".
   - Следующий action усиливает тот же trigger, если он повторяемый.

## UX-copy

- Header: `Книга -> действие -> привычка`
- Memory line: `Помню из вчера: после кофе ты сделал 5 минут чтения. Верно?`
- Buttons: `Верно`, `Исправить`, `Забыть`
- Correction title: `Что поправить?`
- Correction helper: `Это влияет только на следующие habit-шаги по этой книге.`
- Forget state: `Не буду использовать это воспоминание. Сегодняшний шаг построен только на книге и твоей цели.`
- Today action: `Если наливаешь утренний кофе, то открой заметку с одной идеей из Atomic Habits и запиши 1 действие на сегодня.`
- Check-in question: `Ты сделал это после кофе?`

## Открытые вопросы

- Показывать ли confidence явно числом или только человеческой формулировкой вроде "похоже, это сработало"?
- Должно ли `забыть` удалять факт из derived memory сразу или только исключать его из следующих recommendations?
- Где лучше открывать correction UI: bottom sheet или inline edit, чтобы не ломать быстрый check-in?
- Нужно ли показывать source check-in ID пользователю, или достаточно "из вчерашнего check-in"?
