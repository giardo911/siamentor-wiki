# 2026-07-23 - Third Rebuild Action Gate

## Фокус дня

`third_rebuild_action_gate_after_forget`: после privacy reset и двух новых verified/corrected действий показать готовность к третьему новому действию, но не открывать proof paywall до выполнения и проверки именно третьего нового receipt.

## Проблема

После `Забыть` пользователь явно разорвал старую memory-chain. Если продукт после двух новых действий слишком рано возвращает старый proof или показывает paid CTA, paywall начинает продавать не текущую привычку, а устаревшее доказательство. Это ломает доверие к privacy-control и делает книгу -> действие -> привычка непрозрачной.

## Дизайн-решение

Состояние `third_rebuild_action_gate_after_forget` должно быть мобильным checkpoint-экраном в daily habit loop:

- book/thesis anchor остаётся видимым как источник действия;
- progress показывает `2/3 новых проверенных действий`;
- третье действие строится только из последнего нового verified/corrected receipt после reset;
- deleted receipt не используется в DOM, event payload, action source или proof eligibility;
- paid CTA скрыт до завершения третьего действия и explicit receipt review;
- после `Сделал` открывается review receipt, а не paywall напрямую.

## Ключевые состояния

- `new_proof_progress_after_forget_2_of_3`: есть два новых verified/corrected receipt после reset, paywall закрыт.
- `third_rebuild_action_ready`: действие <=5 минут собрано из новой chain, без deleted receipt.
- `third_rebuild_action_completed_pending_review`: пользователь нажал `Сделал`, receipt ждёт `Верно / Исправить / Забыть`.
- `proof_ready_after_third_new_verified_receipt`: только после проверки третьего receipt можно показать evidence receipt + paid CTA + free action на том же экране.

## UX-copy

- Progress: `2/3 новых проверенных действий после сброса`
- Action source: `Следующий шаг из вашей новой цепочки: книга -> действие -> привычка`
- Action title: `Третье действие перед доказательством`
- Paywall blocked: `Подписка откроется после проверки этого действия. Старые удалённые заметки не учитываются.`
- Receipt review CTA: `Проверить действие`

## Открытые вопросы

- Нужно ли явно показывать timestamp privacy reset рядом с progress, или это перегрузит mobile screen?
- Достаточно ли `2/3 новых проверенных действий` для доверия, или нужен мини-список двух новых receipts?
- Должен ли `Исправить` на третьем receipt оставлять paywall закрытым до сохранения исправления как verified/corrected?

## Acceptance contract для product

Spec: `apps/web/e2e/habit-third-rebuild-action-gate-after-forget.spec.ts`

Проверить сценарий:

1. Пользователь нажал `Забыть`, proof reset стал `0/3`.
2. Пользователь выполнил и проверил два новых действия после reset.
3. Экран показывает `2/3 новых проверенных действий после сброса`.
4. Третье действие <=5 минут строится из нового verified/corrected receipt.
5. Deleted receipt не появляется в DOM, analytics payload и action source.
6. Paid CTA отсутствует до `Сделал` + explicit receipt review.
7. После третьего verified/corrected receipt появляется proof paywall с evidence, paid CTA и free action.

Events:

- `new_proof_progress_after_forget_2_of_3`
- `third_rebuild_action_ready`
- `deleted_receipt_excluded_from_third_rebuild`
- `paywall_blocked_until_third_rebuild_review`
- `proof_ready_after_third_new_verified_receipt`
