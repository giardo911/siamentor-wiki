# 2026-06-16 — Единый habit surface

## Фокус дня

Свести ежедневный экран в один mobile-first surface, где пользователь видит цепочку `книга -> действие -> привычка` без перехода в generic chat: сегодняшнее микро-действие, память о вчерашнем шаге, состояние streak/grace и прогресс до proof paywall.

## Проблема

Сейчас отдельные идеи уже описаны: memory trust gate, recovery, proof paywall после 3 действий. Но если они живут как разные экраны, пользователь может не понять главный ритм продукта: книга дает действие, действие повторяется в привычку, привычка открывает платный 30-дневный план. Для consumer UX это должно ощущаться как один спокойный ежедневный ритуал, а не как LMS-модуль или чат с советами.

## Дизайн-решение

Основной экран дня строится вокруг одного вопроса: "что я должен сделать сегодня и почему именно это?". Верхний блок показывает книгу и выбранную идею, центральный блок фиксирует микро-действие до 10 минут, ниже идет проверяемая память и короткий прогресс до paywall proof.

Порядок блоков:

1. Book context: название книги и одна мысль, из которой выросло действие.
2. Today's action: if-then формулировка с trigger, действием и лимитом времени.
3. Memory receipt: `Помню: вчера ты сделал <action> после <trigger>; мешало <friction>`.
4. Trust controls: `верно`, `исправить`, `забыть`.
5. Habit status: streak, grace-state при пропуске, и 0/3, 1/3, 2/3, 3/3 completed actions до proof paywall.
6. Primary CTA: выполнить действие или отметить результат.

## Ключевые состояния

- `day1_action_ready`: первая сессия, memory receipt еще нет; paywall явно blocked до 3 completed actions.
- `day2_7_memory_check`: есть evidence line, пользователь подтверждает или исправляет память перед сегодняшним действием.
- `action_completed`: completed action добавляется в progress strip и становится будущим evidence.
- `missed_24_72h`: surface переключается в calm restart: grace day, evidence snippet, микро-действие до 5 минут.
- `ready_for_proof`: после третьего completed action появляется proof paywall с X/Y/Z действиями, осторожным trigger pattern и 30-day promise.
- `memory_corrected`: следующий action пересобирается только после исправления, чтобы не усиливать неправильный pattern.

## UX-copy

- Header: `Сегодня из книги`
- Action label: `Шаг на 7 минут`
- Memory receipt: `Помню: вчера ты открыл заметки после утреннего кофе. Сложность была в том, что телефон отвлекал.`
- Trust controls: `Верно`, `Исправить`, `Забыть`
- Progress: `2 из 3 действий до 30-дневного плана`
- Paywall blocked hint: `Сначала соберем 3 реальных действия, потом предложим план.`
- Ready copy: `Ты уже сделал 3 шага. Теперь можно усилить ритм на 30 дней.`

## Открытые вопросы

- Нужно ли показывать progress to proof paywall уже на Day 1 или только после первого completed action?
- Должен ли memory receipt быть обязательным gate перед today's action или можно свернуть его после нескольких подтверждений?
- Как избежать ощущения "игрового streak pressure", если продукт должен быть спокойным companion?
- Что считать completed action для paywall proof: только self-report или нужен follow-up вопрос о результате?
