# 2026-07-22 - Новый proof после privacy reset

## Фокус дня

`second_rebuild_receipt_after_forget`: после удаления старой памяти и первого нового действия пользователь должен увидеть, как второе новое действие собирает доказательство привычки заново: книга -> новое действие -> новая проверенная память -> следующий маленький шаг. Paywall все еще закрыт до `3/3` новых verified/corrected receipts.

## Проблема

После `Забыть` продукт уже показывает reset `0/3` и первый recovery step. Следующий риск: пользователь сделал первый новый шаг, но интерфейс может случайно вернуться к старой логике proof, смешать удаленный receipt с новым прогрессом или слишком рано вернуть paid CTA. Для consumer companion это ломает доверие: privacy-control должен ощущаться как реальное начало новой цепочки, а не как косметическая кнопка.

## Дизайн-решение

Сделать отдельное состояние `second_rebuild_receipt_after_forget` для Day 2 после privacy reset:

- показать receipt review по первому новому действию, без текста из удаленного receipt;
- после `Верно` или `Исправить` засчитать `1/3 новых проверенных действий`;
- сформировать второе действие только из book/thesis anchor и нового verified/corrected receipt;
- явно скрыть paid CTA и proof paywall до `3/3` новых receipts;
- удержать action <=10 минут и сохранить mobile-first one-screen flow.

## Ключевые состояния

- `rebuild_receipt_review`: карточка "Проверь новое доказательство" с новым completed action, trigger и friction.
- `new_proof_progress_1_of_3`: строка прогресса "1/3 новых проверенных действий" после подтверждения или исправления.
- `second_rebuild_action_ready`: следующий шаг с bridge "книга -> новое вчерашнее действие -> сегодняшний шаг".
- `paywall_blocked_during_rebuild`: paid CTA скрыт, вместо него показывается причина: "Продолжение откроется после 3 новых проверенных действий".
- `deleted_memory_boundary`: пустое состояние/guard, которое запрещает показывать старый receipt в тексте, analytics payload и eligibility.

## UX-copy

- Header: `Проверь новое доказательство`
- Receipt line: `Вчера ты сделал: 5 минут разобрал один пример из главы про фокус.`
- Progress: `1/3 новых проверенных действий`
- Next action: `Сегодня: перед первой рабочей задачей запиши один отвлекающий фактор и убери его на 10 минут.`
- Paywall boundary: `Платное продолжение пока закрыто: сначала соберем 3 новых проверенных действия после сброса памяти.`
- Correction CTA: `Исправить новое доказательство`
- Forget boundary: `Удаленная память не используется в этом плане.`

## Открытые вопросы

- Нужно ли показывать маленькую ссылку на privacy log, где видно, что старый receipt удален, или это перегрузит mobile screen?
- Считать ли corrected receipt равным verified для `1/3`, если пользователь исправил только wording, но не trigger?
- Какой event должен быть главным для dashboard: `second_rebuild_action_ready` или `new_proof_progress_after_forget_1_of_3`?

## Acceptance contract

Product spec name: `habit-second-rebuild-receipt-after-forget.spec.ts`

Scenario:

1. User previously clicked `Забыть`, completed one new rebuild action, and confirmed or corrected the new receipt.
2. Product shows proof progress as `1/3 новых проверенных действий` and keeps the original book/thesis anchor visible.
3. Product prepares the second rebuild action from the new verified/corrected receipt only.
4. The second action is template-first, <=10 minutes, and uses the new trigger/friction rather than deleted receipt fields.
5. Product emits `second_rebuild_action_ready` with `new_proof_progress_after_forget=1` and `deleted_receipt_excluded_from_rebuild=true`.
6. Paid CTA and proof paywall remain hidden or disabled until `3/3` new verified/corrected receipts.
7. User-facing UI explains the boundary with `Удаленная память не используется в этом плане` or equivalent bounded copy.

Required assertions:

- The screen contains `1/3 новых проверенных действий`, the current book title, the current thesis, and the second rebuild action.
- The second rebuild action payload/source references only the new receipt id or new receipt fields.
- Deleted receipt content is absent from the DOM, analytics payload, action source label, and proof eligibility calculation.
- No paid-start event is emitted at `1/3`, including `paid_30_day_plan_started`, `trial_started_from_proof`, or stale-proof variants.
- `paywall_blocked_during_rebuild` or equivalent state is visible with copy that says paid continuation opens after `3/3` new verified actions.
- Corrected new receipt counts toward `1/3` only after explicit save; an open correction draft must not unlock the second action.

Implementation notes:

- Reuse the `forgotten_receipt_rebuild` and `rebuild_receipt_review` states; add the second-action state as a continuation, not a separate onboarding branch.
- Keep action generation template-first. LLM fallback may only shrink, clarify, or rewrite the second action and must not receive deleted receipt text.
- Recalculate proof eligibility from current verified/corrected receipt ids after every privacy reset and review action.
- Add a negative fixture with recognizable deleted receipt text so the spec can assert it never appears after reset.
