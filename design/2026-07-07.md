# 2026-07-07 - Next action from verified memory

## Фокус дня

Day 2-7 экран следующего действия после memory receipt gate: пользователь подтвердил, исправил или забыл вчерашнюю память, и продукт должен явно собрать новое микро-действие из проверенного receipt, а не из общего профиля.

## Проблема

После Day 1 у SiaMentor уже есть книга, применимый тезис, выполненное действие, trigger и friction. Если на следующий день приложение просто показывает новое действие без объяснения связи, пользователь видит обычный AI-планировщик. Если приложение показывает "память" отдельно, но действие от нее не зависит, memory receipt становится декоративным и не усиливает доверие перед paywall.

Нужно доказать в UX: я прочитал книгу, сделал маленький шаг, продукт запомнил только полезный результат, и следующий шаг адаптирован под реальную попытку.

## Дизайн-решение

После verified memory receipt показывать next action card с явным мостиком:

1. Книга: короткий source snippet или тезис `идея -> поведение`.
2. Вчера: verified `completed_action`.
3. Условие: verified или исправленный `trigger`.
4. Препятствие: verified или исправленный `friction`.
5. Сегодня: одно действие 5-10 минут, сформулированное как if-then step.

Экран не открывает generic chat. Primary CTA: `Сделал`. Secondary: `Слишком сложно` для уменьшения действия до <=5 минут. Tertiary text action: `Исправить память`, если пользователь заметил ошибку уже после просмотра next action.

## Ключевые состояния

- `verified_memory_next_action`: receipt подтвержден, next action явно использует `trigger`, `friction`, `completed_action`.
- `corrected_memory_next_action`: пользователь исправил receipt, next action перестроен на основе исправления; progress не теряется.
- `forgotten_memory_next_action`: пользователь выбрал `Забыть`, next action использует только книгу и текущую цель, без утверждения "помню вчера".
- `too_hard_action_shrink`: действие уменьшено до <=5 минут, friction сохраняется как причина адаптации.
- `completed_day2_action`: после `Сделал` появляется receipt `2/3` с тем, что будет учтено завтра.

## UX-copy

Receipt bridge:

> Беру вчерашний шаг, который ты подтвердил: "10 минут без телефона после кофе".

Next action:

> Сегодня: после утреннего кофе положи телефон в другую комнату и открой книгу на одном отмеченном абзаце. 7 минут.

Why this:

> Учитываю препятствие: телефон остается на столе и перетягивает внимание.

CTA:

- `Сделал`
- `Слишком сложно`
- `Исправить память`

Completion receipt:

> Прогресс 2/3. Завтра я опираюсь на этот шаг и проверю, стал ли trigger легче.

## Открытые вопросы

- Нужно ли показывать full receipt на этом экране или достаточно свернутого bridge из 1-2 строк?
- Должен ли `Слишком сложно` сразу менять сегодняшнее действие или сначала задавать один friction-вопрос?
- Считать ли `forgotten_memory_next_action` eligible для proof paywall, если действие выполнено, но receipt не verified?
