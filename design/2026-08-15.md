# 2026-08-15 — Seventh Decline Receipt Return

## Фокус
`seventh_decline_receipt_return`: после седьмого отказа от paid CTA, бесплатного действия и проверки результата вернуть пользователя в живую цепочку, а не в hard paywall.

## Проблема
Пользователь уже семь раз отклонил оплату, но продолжает доказывать привычку действиями. Если после verified/corrected receipt сразу показать жесткую оплату, продукт наказывает за выполненное действие и ломает связку книга -> действие -> привычка.

## Дизайн-решение
Показать success state `Проверено. Цепочка продолжается` с прогрессом `12 проверенных действий после сброса`. Основной экран сначала закрепляет книгу и тезис, затем дает следующее действие <=5 минут из `rebuilt_verified_chain`; paid CTA возвращается только ниже действия как мягкое предложение усилить поддержку.

## Ключевые состояния
- Entry: `seventh_decline_receipt_verified` или `seventh_decline_receipt_corrected`.
- Success: receipt сохранен в новую verified chain, deleted receipt не попадает в DOM, event payload, action source и proof source.
- Next action: одна конкретная микро-задача из книги, <=5 минут, с кнопкой `Сделал`.
- Monetization: paid CTA ниже action, без блокировки основного действия; dismiss оставляет next action доступным.
- Regression: нельзя показывать price/trial/hard paywall над действием или вместо действия.

## UX-copy
- Заголовок: `Проверено. Цепочка продолжается`
- Прогресс: `12 проверенных действий после сброса`
- Book anchor: `Из книги: «Atomic Habits»`
- Thesis anchor: `Маленькое действие закрепляет привычку лучше, чем большой план.`
- Action: `Положи книгу на место, где завтра увидишь ее до телефона.`
- Primary CTA: `Сделал`
- Paid CTA below action: `Хочешь, я каждый день буду подбирать следующее действие из книги?`
- Paid button: `Продолжить с наставником`
- Dismiss: `Не сейчас`

## Acceptance contract
Target spec: `apps/web/e2e/habit-seventh-decline-receipt-return.spec.ts`.

Required assertions:

- after `seventh_decline_receipt_verified` or `seventh_decline_receipt_corrected`, render state `seventh-decline-receipt-return`;
- show success `Проверено. Цепочка продолжается` before any monetization copy;
- show progress `12 проверенных действий после сброса`;
- show book/thesis anchor before the next action;
- show exactly one next action <= 5 minutes from `rebuilt_verified_chain`;
- keep paid CTA, price and trial below the next action, never as a blocking surface;
- emit `seventh_decline_receipt_return_shown`, `seventh_decline_return_paid_cta_seen`, `seventh_decline_return_paid_cta_dismissed` and `seventh_decline_return_next_action_completed`;
- deleted/forgotten receipt is excluded from DOM, event payload, next action source and proof source.

## Product handoff

Suggested fixture state for the product spec:

- route: `/ru/habits/rebuild-proof?state=seventh-decline-receipt-return`;
- entry events: `seventh_decline_receipt_verified` or `seventh_decline_receipt_corrected`;
- verified progress before return: `12`;
- progress copy: `12 проверенных действий после сброса`;
- action source: `rebuilt_verified_chain`;
- forbidden blocking copy before the action: `999 ₽`, `30 дней`, `trial`, `Продолжить с наставником`;
- required privacy fixture: one deleted pre-reset receipt with a unique marker that must not appear in DOM, analytics payload, next action source, or proof source.

Implementation note: land the pending sixth/seventh free-loop product states first, then implement this return state with the shared rebuild-proof scenario pattern so repeated-decline handling stays deterministic.

## Открытые вопросы
- Когда серия отказов должна превращаться в другой pricing experiment, если пользователь стабильно выполняет действия?
- Нужно ли менять paid CTA copy после 7+ dismiss на более легкий тон без trial/price?
- Должен ли progress показывать общий streak отдельно от `после сброса`, чтобы не обесценивать старую привычку?
