# 2026-07-25 - Paywall after final rebuild receipt

## Фокус дня

`paywall_after_final_rebuild_receipt`: после privacy reset и review третьего нового receipt показать proof paywall только для новой проверенной цепочки.

## Почему это важно

Предыдущий gate защищает момент до проверки третьего receipt. Следующий риск появляется сразу после проверки: paywall может случайно продавать старое доказательство или generic AI-доступ. Для SiaMentor это ломает обещание "book -> action -> repeat -> proof -> paid -> retained": платный CTA должен опираться на три новые проверенные действия после сброса, а deleted receipt не должен попадать ни в UI, ни в аналитику, ни в source следующего действия.

## Acceptance contract

Spec: `habit-paywall-after-final-rebuild-receipt.spec.ts`

Scenario:

1. Пользователь нажал `Забыть` на старом receipt, и proof eligibility сброшен.
2. Пользователь выполнил и проверил три новых действия из новой цепочки.
3. После review третьего receipt продукт показывает proof paywall `3/3 новых проверенных действия после сброса`.
4. Paywall содержит book/thesis anchor, paid CTA `Продолжить 30 дней`, цену, free continue action и не содержит deleted receipt.
5. Paid CTA отправляет `trial_started_from_rebuilt_proof`, а бесплатное продолжение отправляет `free_continue_after_rebuild_clicked`.

Required assertions:

- DOM содержит `3/3 новых проверенных действия после сброса`;
- book/thesis anchor сохранены;
- paid CTA и `999 ₽ за 30-дневный план` видимы только после финального receipt review;
- free continue action видим, <=5 минут и построен из новой цепочки;
- deleted receipt отсутствует в DOM, event payload, proof eligibility и action source;
- `paywall_after_final_rebuild_receipt_shown` и `habit_paywall_proof_rendered` несут `proof_chain=rebuilt_after_forget`;
- legacy `trial_started_from_proof` не используется для новой rebuilt-chain monetization.

Negative fixture:

- Deleted receipt text: `старый удаленный инсайт про вечерний телефон`.
- New receipt 1: `5 минут выписал рабочий триггер перед первой задачей`.
- New receipt 2: `10 минут убрал один отвлекающий фактор и отметил результат`.
- New receipt 3: `5 минут сделал третий шаг из новой цепочки`.

## Implementation notes

- Reuse the final-receipt review state from `final_rebuild_receipt_before_paywall`.
- The proof screen should read only verified/corrected receipt ids from the post-reset chain.
- The free continue action should use sanitized current-chain context, not old receipt text.
- Keep `paid_30_day_plan_started` for revenue-facing contract if the actual payment start exists; use `trial_started_from_rebuilt_proof` only as the rebuilt-proof CTA acceptance event until billing is wired.
