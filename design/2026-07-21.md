# 2026-07-21 - Recovery proof after new action

## Фокус дня

`rebuild_proof_after_forget_action`: после того как пользователь нажал `Забыть` и сделал новое маленькое действие, продукт должен показать, что цепочка книга -> действие -> привычка восстановилась с нового доказательства, а не вернулась к удаленному receipt.

## Проблема

Сценарий `Забыть` уже защищает privacy-control: старый receipt исключается из next action и stale proof CTA блокируется. Но следующий важный момент - первое новое выполненное действие после forget. Если интерфейс просто показывает обычный progress, пользователь может не понять, что удаленная память действительно не вернулась, а paywall снова будет открыт только на новых verified/corrected действиях.

Это критично для consumer-grade companion: доверие строится не на обещании "мы забыли", а на видимой новой цепочке поведения.

## Дизайн-решение

После completion нового действия из `forgotten_receipt_rebuild` показать recovery receipt review:

- Верхняя строка: `Новая цепочка началась`
- Book anchor остается прежним: книга и тезис видны как источник идеи
- Старый receipt не упоминается и не используется
- Новый pending receipt показывает только новое действие, новый trigger и новую friction-note
- Proof progress: `1/3 новых проверенных действий`
- Primary action: `Верно`
- Secondary action: `Исправить`
- Destructive/privacy action: `Забыть`
- Paywall CTA скрыт до `3/3` новых verified/corrected receipts

После `Верно` или сохраненного `Исправить` следующий action строится template-first из нового receipt и остается <=10 минут.

## Ключевые состояния

1. `forgotten_receipt_rebuild_action_completed`
   - Пользователь выполнил новое действие <=5 минут после forget.
   - UI показывает recovery receipt review, а не proof paywall.

2. `new_receipt_verified_after_forget`
   - Пользователь подтвердил новый receipt.
   - Progress становится `1/3 новых проверенных действий`.
   - Next action использует только новый trigger/friction.

3. `new_receipt_corrected_after_forget`
   - Пользователь исправил trigger или friction.
   - Исправленный receipt считается proof-eligible только после явного сохранения.

4. `paywall_still_blocked_after_first_rebuild`
   - Paid CTA не появляется при `1/3`.
   - Если пользователь пришел через stale proof entrypoint, показывается rebuild progress, а не покупка.

## UX-copy

- Заголовок: `Новая цепочка началась`
- Подзаголовок: `Я больше не использую забытое действие. Это первое новое доказательство по книге.`
- Progress: `1/3 новых проверенных действий`
- Receipt label: `Проверить новое действие`
- Primary: `Верно`
- Secondary: `Исправить`
- Privacy: `Забыть`
- Paywall boundary: `Продолжение на 30 дней откроется после 3 новых проверенных действий.`

## Открытые вопросы

- Нужен ли отдельный copy для случая, когда пользователь исправил новый receipt: `1/3 новых проверенных действий после исправления` или достаточно общего progress?
- Должен ли old proof history быть доступен в settings/history как deleted metadata без action details, или лучше полностью не показывать его в consumer UI?
- Считать ли `new_receipt_after_forget_created` отдельным milestone в onboarding analytics или только recovery event?

## Acceptance contract

Product spec name: `habit-rebuild-proof-after-forget-action.spec.ts`

Scenario:

1. User has deleted a previous receipt through `Забыть` and sees `forgotten_receipt_rebuild`.
2. Product shows the preserved book/thesis anchor and one template-first action <=5 minutes that does not reuse deleted receipt fields.
3. User clicks `Сделал` on the rebuild action.
4. Product emits `forgotten_receipt_rebuild_action_completed` and opens recovery receipt review, not the proof paywall.
5. Recovery review shows the new completed action, new trigger, new friction note, and `1/3 новых проверенных действий`.
6. Clicking `Верно` emits `new_receipt_verified_after_forget`; clicking saved correction emits `new_receipt_corrected_after_forget`.
7. The next action uses only the new verified/corrected receipt and stays <=10 minutes.
8. Paid CTA remains hidden or disabled until `3/3` new verified/corrected receipts; stale proof entrypoints keep showing rebuild progress instead of checkout.

Required assertions:

- `paywall_still_blocked_after_first_rebuild` is emitted with `proof_progress_after_rebuild=1`.
- No paid-start event is emitted at `1/3`, including `paid_30_day_plan_started`, `trial_started_from_proof`, or `trial_started_from_stale_proof`.
- User-facing copy contains `Новая цепочка началась`, `1/3 новых проверенных действий`, the current book title, and the current thesis.
- The DOM or event payload proves deleted receipt content is excluded from the next action source.
- Corrected new receipt becomes proof-eligible only after explicit save, not while the correction form is open.

Implementation notes:

- Reuse the `forgotten_receipt_rebuild` state and add a follow-up review state rather than creating a separate recovery flow.
- Keep recovery action generation template-first; LLM fallback may only shrink/clarify/rewrite new action copy and must not receive deleted receipt text.
- Proof eligibility should be recalculated from current verified/corrected receipts after each review action, not from cached proof paywall state.
