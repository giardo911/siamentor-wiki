# 2026-07-13 - Template-first next action after verified memory

## Фокус дня

`verified_memory_next_action_template`: после подтвержденного или исправленного receipt прошлого дня следующий шаг собирается из структуры книги и привычки, а не из свободного AI-чата.

Цепочка должна быть видна на одном mobile-first экране: книга -> вчерашнее действие -> trigger/friction -> сегодняшнее действие -> receipt.

## Проблема

После Day 1 пользователь уже дал системе самый ценный сигнал: что он реально сделал, где хотел сделать и что помешало. Если Day 2 снова выглядит как "спроси AI что делать", продукт теряет consumer-grade ощущение привычки, повышает LLM-cost и рискует предложить неправильный следующий шаг.

Нужно сделать так, чтобы verified memory сразу превращалась в конкретное действие <=10 минут. LLM может помогать только в узких fallback-сценариях: уменьшить слишком сложный шаг, переформулировать trigger или уточнить непонятную friction.

## Дизайн-решение

Экран Day 2-7 открывается с компактного bridge-блока:

- Книга: "Atomic Habits", тезис: "сделай привычку очевидной".
- Вчера: "положил книгу на подушку после ужина".
- Помню: trigger "после ужина", friction "забываю, если телефон рядом".
- Сегодня: "после ужина положи телефон на зарядку в другой комнате и открой книгу на 2 страницы".

Primary action: `Сделал`.

Secondary actions:

- `Уменьшить` - shrink fallback, если действие кажется слишком большим.
- `Исправить память` - возврат к memory receipt.
- `Не сегодня` - recovery hook с одним <=5 минут действием позже.

Важно: на экране нет generic input "что хочешь обсудить?". Пользователь может выполнить, уменьшить или исправить, но не проваливается в open-ended chat.

## Ключевые состояния

- `template_action_ready`: есть verified/corrected receipt, действие собрано локально из `goal`, `book_thesis`, `trigger`, `completed_action`, `friction`.
- `template_action_shrunk`: пользователь нажал `Уменьшить`, действие стало <=5 минут, сохраняется тот же trigger.
- `template_fallback_used`: LLM вызван только для shrink/clarify/rewrite, событие содержит `fallback_reason`.
- `template_action_completed`: пользователь нажал `Сделал`, создается receipt с progress `2/3` или текущим day index.
- `template_memory_mismatch`: пользователь нажал `Исправить память`, следующий action пересобирается только после verify/correct.

Fallback copy: "Сделаем меньше: после ужина просто поставь телефон на зарядку в другой комнате. Книгу откроешь завтра."

Boundary copy: "Я помню только цель, trigger, действие и препятствие для этой привычки."

## Открытые вопросы

- Нужно ли показывать `llm_calls_used=0` в internal debug/dashboard или достаточно события `template_action_ready`?
- Считать ли `Уменьшить` негативным сигналом качества исходного template action или нормальным personalization step?
- Как быстро после `Исправить память` пересобирать action: сразу на том же экране или через отдельный receipt confirmation?
