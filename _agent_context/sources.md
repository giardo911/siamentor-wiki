# Sources And Refresh

Updated: 2026-07-12

## Authority levels

1. Production code and typed analytics contracts are authoritative for what the product actually emits.
2. `strategy/` is authoritative for durable product direction.
3. `project-checklist.md` is authoritative for current execution order.
4. `daily/` and `design/` are raw logs and decision evidence.
5. External articles are supporting evidence, not product truth.

## Refresh cadence

Refresh this overlay when:

- a CEO checklist item is completed or reprioritized;
- a typed event contract changes;
- a paywall, habit-loop, or memory behavior ships;
- strategy changes the wedge, price, funnel, or north-star metric.

Routine daily notes do not require updating every overlay page. Update only the pages whose current truth changed.

## Agent workflow

1. Start with [[index]].
2. Read [[current-state]], [[metrics]], and [[backlog]] before product work.
3. Open raw source links only when the task needs supporting detail.
4. After changing source files, update this overlay if a durable decision, metric, or priority changed.
5. Keep diffs inspectable and small.

## Freshness checks

Before acting on a metric or event name, verify against production code or typed contracts when available. If this overlay conflicts with code, code wins and the overlay should be updated.
